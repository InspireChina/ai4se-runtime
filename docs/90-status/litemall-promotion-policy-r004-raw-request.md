# R-004 原始需求：结算优惠推荐与互斥策略

运营希望在商城结算确认页向用户展示“当前订单可用的优惠券推荐”，降低用户错过优惠的概率。

现有订单确认、优惠券资格与优惠金额计算逻辑必须继续作为服务端唯一权威；本卡不新增数据库表，不改变既有优惠券发放、核销或团购创建流程。

需要支持以下业务结果：

- 对当前用户、当前购物车和当前结算商品，返回可用优惠券候选及推荐顺序；
- 推荐必须按最终可抵扣金额排序，并处理相同金额的稳定规则；
- 用户必须能明确选择一张优惠券，且同一订单不能同时享受优惠券和团购/拼团优惠；
- 非法、过期、不满足门槛或不属于当前用户的券不能改变订单优惠金额；
- 原有未选择优惠券的结算、下单和金额计算必须保持兼容；
- 后端要有可重复的自动化测试覆盖正常推荐、门槛不满足、并列、团购互斥和恶意 couponId。

以下业务含义尚未由本需求决定，必须在 Specification/Analysis 形成带证据的选项并等待确认：

1. 推荐是否会自动选中/应用最优券，还是只展示推荐？
2. 可抵扣金额相同的券，采用什么稳定排序？
3. 团购订单遇到可用券时，是完全不展示、展示但禁止选择，还是允许叠加？
4. 推荐接口如何兼容已有结算 API，是否新增字段/端点？
5. 面额高于订单金额、或优惠后金额为负时，采用什么封顶规则？

这是 AI4SE 真实验证卡。产品回答会在后续单独记录；禁止把本文件中的未决项当成默认规则。
